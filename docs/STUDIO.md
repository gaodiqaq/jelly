# Jelly Studio 使用说明

Jelly 的 Web 端现在围绕作品、文件版本和可复用工作方法组织。

## 使用

运行 `start_jelly.bat`，浏览器打开 http://localhost:8000。若旧服务仍在运行，先停止旧实例再启动。前端源码有修改时，在 `webui` 中运行 `npm run build`。

- **项目工作区**：侧栏「项目」旁点击 `＋`，输入名称即可在显示的位置自动创建专属目录，也可切换为绑定已有目录。新目录默认位于用户主目录的 `Jelly Projects`，可通过 `AGENT_PROJECTS_ROOT` 指定位置；容器使用 `/workspace/JellyProjects` 持久化。项目创建后目录固定；点击顶部项目名称修改其他设置。模型留空时跟随全局默认，提供商凭据由全局设置管理。
- **项目归档**：在项目设置中归档暂时不用的项目。归档不会删除任务、版本或工作目录；项目仍可从「已归档」查看，恢复后才能新建或继续执行任务。运行中的项目不能归档。
- **新建任务**：先选择项目再新建任务。目录、历史、文件预览和恢复跟随任务归属，切换项目不会改写其他项目的工作目录。不同项目可同时运行任务。
- **对话布局**：左侧项目与最近任务，中间对话 / 执行记录 / 文件，右侧成果预览。工具步骤默认收起，点击查看输入与结果；输入区集中放置权限、模型和技能入口。
- **成果自动打开**：通过 `write/edit` 生成的项目内文件会出现在成果卡片中，并自动打开预览。同一批文件优先展示 Markdown 或 HTML。点击其他成果可形成多个文件标签；同名文件按任务目录读取。
- **成果与版本**：查看本会话通过 `write/edit` 修改的文件、时间和文本 Diff。点击文件进入预览。
- **恢复此修改**：展示确认后恢复修改前的原始字节；新建文件的恢复会删除该文件。如果当前内容已被后续操作改变，拒绝覆盖。运行中及只读权限下不可恢复。
- **文件预览**：支持 Markdown、代码、图片与隔离的 HTML。HTML 默认采用不执行脚本的静态预览；用户可显式开启隔离交互模式运行内联脚本。交互 iframe 不共享父页面来源，也不允许网络请求或顶层导航。
- **工作配方**：从本次目标起草工作步骤，手动审阅、编辑并保存。使用配方只填入输入框，由用户补充材料后提交。修改配方会递增版本号，目前保留最新内容。
- **文档阅读**：Markdown 使用独立阅读排版、目录导航和源文件切换，支持下载及专注阅读（Esc 退出）。右侧「版本与恢复」查看代码或文档的修改差异。
- **主题与尺寸**：默认炭灰与鼠尾草绿，右上角可切换浅色；偏好保存到当前浏览器。桌面保持三栏，窄屏使用可关闭的预览抽屉。

## 执行语义

Web 使用独立的 `RunService` 管理任务，每个会话最多同时运行一次。浏览器通过 REST 轮询运行快照，运行中约 650 ms 一次，空闲约 2.5 秒一次；连接失败自动重试。停止按钮表示请求取消，执行器退出前保持运行状态。

每轮固定项目目录、模型、凭据与权限，设置修改影响后续轮次。项目会话保存 `project_id` 与原始目录；未归属项目的旧会话继续使用原有全局工作区设置。全局目录切换保留运行中保护，且不会更新项目会话。任务启动、关键事件和结束时写入运行记录。服务重启会将未结束的记录显示为中断，不自动重放工具。

旧 WebSocket API 保留兼容；旧客户端仍沿用断开时取消的行为。CLI 工具行为保留；文件版本记录目前接入 Web 执行器。

## 数据与边界

原有 JSONL 会话无需迁移。在会话目录下新增：

- `changes/<session_id>/<change_id>.json`：修改前后内容及恢复状态。
- `runs/<session_id>.json`：最近一次运行的状态快照。
- `recipes/<recipe_id>.json`：用户审阅过的工作配方。
- `projects/<project_id>.json`：项目名称、固定目录、默认模型及权限。多用户模式下保存在各自会话目录中。

这些文件包含本地工作内容，应与会话历史一起备份。文件恢复只覆盖工作区内、可建立快照的 `write/edit` 操作；不包含 Bash、网络请求、外部服务及其他副作用。现有文件在修改前若已超过 2 MB，会拒绝执行该文件工具；新文件写入后若超过快照上限，写入仍视为成功，但会明确提示该版本无法恢复。

项目隔离指任务归属、相对工作目录、预览、文件版本和执行设置的隔离，并非操作系统沙箱。两个项目若主动选择同一目录，底层文件仍然共享；Bash 等工具也不是系统级隔离。恢复使用内容一致性检查与进程内锁，无法为外部进程提供文件系统级事务隔离。

自动成果发现目前覆盖成功记录的 `write/edit` 操作。Bash 或外部程序产生的文件仍可从文件树打开，但不会自动生成版本卡片。工作配方和提供商连接按用户共享。多进程 worker、分布式任务恢复、完整事件回放、自动提炼配方、配方历史回滚和上下文摘要尚未实现。

项目测试进一步覆盖同名文件预览与恢复、目录固定、重载持久化、项目权限、并行运行和用户目录隔离。离线浏览器验收脚本与截图生成方式见 [开发与验证](DEVELOPMENT.md)。
